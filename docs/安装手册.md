# TokenScope 安装手册

本文档说明 TokenScope 的完整安装、启动与配置步骤。适用于 Windows（git-bash / PowerShell）与 Linux / macOS。

- 项目主页：见 [README](../README.md)
- 功能使用：见 [使用手册](使用手册.md)

## 1. 环境要求

| 依赖 | 版本要求 | 用途 |
|---|---|---|
| Python | 3.8+（本机验证 3.11） | 后端服务，**纯标准库，无需 pip 安装任何包** |
| Node.js | 18+（本机验证 22） | 仅前端构建时需要 |
| npm | 随 Node.js 安装 | 前端依赖安装 |

> 如果只是使用已构建好的版本（`web/dist` 存在），**不需要 Node.js**，仅需 Python 即可运行。

**支持平台**：Windows（git-bash / PowerShell）、Linux、macOS。平台差异：

| 项 | Windows | macOS / Linux |
|---|---|---|
| 工具数据位置 | `%LOCALAPPDATA%\hermes`、`~\.codex`、`~\.claude`、`~\.zcode` | `~/.hermes`、`~/.codex`、`~/.claude`、`~/.zcode`（自动发现已适配） |
| 启动脚本 | git-bash 下 `./start.sh`（或 `python server.py`） | `./start.sh`（直接可用） |
| 项目路径解码 | Claude 目录名按 Windows 盘符规则解码 | 按 `/` 分隔规则解码 |

## 2. 安装步骤

### 2.1 获取项目

将 `tokenscope` 整个目录复制到目标机器，例如 `D:\software\Hermes\tokenscope`。

### 2.2 构建前端（首次或前端代码有改动时）

```bash
cd web
npm install
npm run build
cd ..
```

- `npm run build` 会执行 TypeScript 类型检查 + Vite 生产构建，产物输出到 `web/dist`。
- 构建完成后 `web/dist` 由后端自动伺服，无需额外配置 Web 服务器。
- 国内网络可配置 npm 镜像加速：`npm config set registry https://registry.npmmirror.com`

### 2.3 检查 Python 可用

```bash
python --version
```

若提示找不到命令，Windows 可尝试 `py --version`，或安装 Python 后勾选"Add to PATH"。

## 3. 启动服务

### 3.1 一键脚本（推荐）

```bash
./start.sh        # 后台启动，日志写入 logs/tokenscope.log
./stop.sh         # 停止
./restart.sh      # 重启
```

脚本特性：

- 自动检测端口占用并提示
- 后台运行 + PID 文件管理（`.tokenscope.pid`）
- 启动后自动健康检查（最长等待 15 秒，确认服务就绪）
- 停止时优雅终止，超时强制结束；Windows 下残留进程自动用 taskkill 兜底

常用自定义：

```bash
PORT=9000 ./start.sh        # 自定义端口
HOST=0.0.0.0 ./start.sh     # 监听所有网卡（局域网访问，注意安全）
```

### 3.2 直接运行（调试用）

```bash
python server.py                    # 默认 127.0.0.1:8787，自动打开浏览器
python server.py --port 9000        # 指定端口
python server.py --no-browser       # 不自动打开浏览器
```

## 4. 验证安装

浏览器访问 `http://127.0.0.1:8787/`，应看到 TokenScope 仪表盘页面，包含：

- 顶部统计卡片（输入 / 输出 / 缓存读取 / 推理 Tokens 等）
- Token 消耗趋势图
- 按模型 / 按工具 / 按来源 / 按任务分组图

命令行验证：

```bash
curl http://127.0.0.1:8787/api/health
# 期望输出: {"ok": true, "app": "TokenScope", "version": "0.3.0", "sources": 4}
```

`sources` 数字 = 自动发现的工具数据源数量（Hermes、Codex、Claude Code、zcode，缺哪个工具就没有哪个）。

## 5. 数据源说明

启动时自动发现以下本地数据（全部**只读**，**无需手动配置**）：

| 工具 | 自动发现路径 | 说明 |
|---|---|---|
| Hermes | `%LOCALAPPDATA%\hermes\state.db` + `profiles\*\state.db` | 主实例与各 profile（支持 `HERMES_HOME` 覆盖） |
| Codex | `~\.codex\state_*.sqlite`（自动取版本号最新） | 会话索引 + `sessions\**\rollout-*.jsonl` 用量明细；支持 `CODEX_HOME` 覆盖数据目录 |
| Claude Code | `~\.claude\projects\` | 按项目目录扫描 `*.jsonl`；支持 `CLAUDE_CONFIG_DIR` 覆盖配置目录 |
| zcode | `~\.zcode\cli\db\db.sqlite` | 请求级用量表；支持 `ZCODE_HOME` 覆盖数据目录 |

> 若某工具的数据目录不在默认位置（如通过环境变量自定义了目录），设置对应环境变量即可被自动发现，无需手动添加。

手动添加其他数据源（如从其他机器拷贝的数据库文件）：在页面「数据源」→「添加数据源」中填写路径并选择类型。

## 6. 配置文件

`config.json`（项目根目录，首次运行自动生成/合并）：

- `sources`：数据源列表（自动发现的源每次启动合并，手动添加的源持久保存）
- `pricing`：模型定价表（在页面「定价设置」中编辑保存）

> 卸载时直接删除整个 `tokenscope` 目录即可，不残留任何系统级文件，不修改任何工具原始数据。

## 7. 常见问题

**Q1：启动后页面显示"前端未构建"？**
后端找不到 `web/dist`。执行 `cd web && npm install && npm run build`。

**Q2：端口被占用？**
`start.sh` 会提示。可 `PORT=9000 ./start.sh` 换端口，或先 `./stop.sh` 停止旧实例。
Windows 下确认残留进程：`netstat -ano | grep 8787`，然后 `taskkill /F /PID <pid> /T`。

**Q3：某个工具没有数据？**
该工具尚未安装使用（如没有 `~/.claude` 目录），或数据文件为空。数据源页面可查看各源状态（存在/缺失、会话数）。

**Q4：成本显示"—"？**
模型未配置定价。到「定价设置」点击「填充示例定价」或手动填写单价（USD / 每百万 tokens）。

**Q5：Claude Code 数据首次加载慢？**
首次扫描 `~/.claude/projects` 约 2 秒，之后有内存缓存，毫秒级响应。

**Q6：支持局域网/内网访问吗？**
`HOST=0.0.0.0 ./start.sh` 即可，浏览器用 `http://<服务器IP>:8787/` 访问。注意放行防火墙端口。

**Q7：迁移到另一台机器？**
拷贝整个目录 + `config.json`（含定价表）即可；数据源为绝对路径，若用户目录不同，删除 `config.json` 让其重新自动发现，或手动重新添加数据源。
